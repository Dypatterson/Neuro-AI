## Findings to carry forward

- **Full spec-4a guard (escalation):** `_consolidate_codebook` draws from the
  **global** torch RNG (via Hopfield retrieve / C.2), not only
  `substrate.generator`. The full checkpointed-vs-non-checkpointed byte-identity
  test must `torch.manual_seed()` before each consolidation, and probe the
  next-drawn vector rather than `Generator.get_state()` (its offset is unreliable
  once MPS is initialised). Today's narrow guard
  ([tests/test_frameb_eval_isolation.py](tests/test_frameb_eval_isolation.py))
  is codebook-only and does not need this.
- **Verdict firewall is premature** and was deferred: only the `G0->*` level
  classifier exists (`gate0_frame_a.py:_classify_verdict`); there is **no
  `FB->*` slope classifier** yet. When the slope classifier is built, bake the
  type-disjoint verdict enum into it at creation rather than retrofitting.
- **`n_consolidation_events` is a misnomer** (counts `observe()` calls, not
  consolidations; only ~11 fire over 1000 obs at `consolidation_k=100`). It is a
  public CLI flag used by gate0 + 9 colab notebooks + 11 test sites, so it was
  **not** hard-renamed; `c3.run()` now accepts an `n_observations` alias and the
  emitted JSON key string is preserved for downstream variance tooling.

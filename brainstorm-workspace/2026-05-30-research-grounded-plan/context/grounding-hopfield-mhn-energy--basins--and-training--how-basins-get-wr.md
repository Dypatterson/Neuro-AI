# Grounding: Hopfield/MHN energy, basins, and TRAINING (how basins get written)

**Primaries opened:** pdf:dense-associative-memory-2016, pdf:ham-2021, pdf:hen-2024, pmc:PMC12017325, arxiv:2411.05849, arxiv:2502.05164, reports/062, reports/063, reports/064

**Card-only:** arxiv:2008.02217, arxiv:2506.10801, arxiv:2410.13866, arxiv:2411.08590, arxiv:2603.20115, arxiv:2412.05562, doi:10.1126/sciadv.adu6991

## Summary
The cluster's load-bearing finding: in every Hopfield/DAM/MHN result where basins encode discriminative or role-like structure, those basins are WRITTEN by a gradient on a target (DAM backprop on labels — opened; HAM BPTT — opened; In-Context Denoising offline gradient on clean targets — opened at abstract depth) or by a learned pre-encoder that improves pattern separability (HEN — opened). The beta/energy nonlinearity and sparse-kernel redesigns only control how SHARPLY already-written vectors separate into basins (Krotov-Hopfield feature<->prototype transition; HEN LSE/beta; opened) — they are readout sharpeners, not writers. Input-driven plasticity (IDP/Betteti, full text opened via PMC) looks like a writer but is a transient landscape tilt that re-weights EXISTING memories and writes nothing persistent; the authors defer a real learning rule to future work. The project's MHN stores atoms as-is (code-confirmed: store() appends raw vectors; retrieval is X^T softmax(beta X s)), so the role-target occupies a random atom's basin-depth distribution. The empirical anchors (reports 062/063/064, re-opened) confirm the consequence: hit_role=0.000 exactly across four retrieval families, and SHARPENING interventions made recovery monotonically WORSE (rank_role 205->498 in E1, which was itself an IDP-style field) — an anti-overlap signature meaning the structure is ABSENT, not entangled. M1 (064) shows a non-degenerate role-discriminative READOUT exists but 'doesn't point at role-target basins,' cleanly separating the solved readout problem from the unsolved writing problem (and validating that GSBC is correctly parked). The one mechanism class that could write role structure without a homunculus is an OFFLINE error-driven consolidation pass with a target that is a FIXED function of the cue (not a supervisor-chosen label) — STATUS already permits batch-offline error-driven updates and bans them online. The decisive open question, unanswered by any opened primary, is what supplies that target unsupervised in an FHRR substrate; this is exactly the kickoff seed's Stage-1 write-then-read go/no-go. Six link_only sources returned only abstract-level detail and are flagged card-only; smoke-strength (n=3) empirical claims are not graduation-strength.

## Supported claims

- **pdf:dense-associative-memory-2016** (primary_opened=True): In Dense Associative Memory (DAM), the stored memory vectors are not stored as-is for the task: they are LEARNED/WRITTEN by gradient descent (backpropagation) on a task objective with explicit target outputs. 'To learn effective memories... an objective function is defined which penalizes the discrepancy between the output c_alpha and the target output... minimized using a backpropagation algorithm. The learning starts with random memories... backpropagation then finds a collection of K memories which minimize the classification error.' The basins are shaped by the loss, not by storing inputs verbatim.
  - _caution:_ This is supervised classification on MNIST/XOR with labels as targets. It demonstrates that a target objective CAN write discriminative basins, but it does not show this is anti-homunculus-clean for an unsupervised consolidation setting, nor that it works in FHRR.

- **pdf:dense-associative-memory-2016** (primary_opened=True): What the energy nonlinearity (power n, equivalently inverse-temperature beta) buys is the feature<->prototype transition and basin sharpness: 'For large n the function F(x) peaks much more sharply around each memory... at large n all the information about a digit must be written in only one memory, while at small n this information can be distributed among several memories.' Small n = distributed features cooperating; large n = each memory specializes to one class (one sharp basin). 'The dominant contribution shaping the basins of attraction comes from the low energy states... determined by the asymptotics of the activation function f(x).' Higher n packs more memories before crosstalk but is purely a retrieval/energy-geometry property over already-written vectors.
  - _caution:_ beta/n controls how SHARPLY existing stored vectors are separated into basins; it does NOT write a role->target association. Sharpening an already-flat (unwritten) signal cannot manufacture a basin — this is exactly what reports 062/063 found.

- **pdf:hen-2024** (primary_opened=True): The continuous MHN energy is the log-sum-exp (LSE) with inverse temperature beta controlling the sharpness of an argmax-over-stored-memories selection: 'E1 = -1/beta log sum_n exp(beta <xi_n, s>)'. The stored memories Xi are the pattern bank; retrieval is energy minimization that treats memories as attractors recoverable from partial cues. beta high = single-pattern fixed point; beta low = averaged/metastable mixture.
  - _caution:_ This confirms the standard MHN stores patterns as-is in Xi and only the energy/temperature is tuned at retrieval. It is the same store-as-is regime the project uses.

- **pdf:hen-2024** (primary_opened=True): HEN's contribution is that meta-stable (spurious) states arise from WEAK SEPARABILITY of the stored patterns, and the fix is to pre-encode inputs through a LEARNED encoder-decoder before storage so patterns are more separable: 'we address the issue of meta-stable states... by improving the separability of input patterns through neural encoding representations... encodes inputs into a latent representational space using a pre-trained neural encoder-decoder model before storage, and decodes them upon recall.' Separability — not the retrieval rule — gates whether a stored pattern forms a recoverable basin.
  - _caution:_ HEN still stores patterns as-is in the MHN; the learning lives in a SEPARATE pre-trained encoder. It improves legibility of already-distinct patterns; it does not write a role->target association where none exists. Card warns: 'HEN does not prove the project has role basins.'

- **pdf:ham-2021** (primary_opened=True): Hierarchical Associative Memory (HAM) constructs attractors compositionally: 'the attractor states are constructed representations that are assembled from primitives encoded in the synaptic weights of lower layers, with assembling rules encoded in the synaptic weights of the higher layers,' and crucially 'HAMs can be trained end-to-end using backpropagation through time.' The global energy is fixed by tying feedback weights = transpose of feedforward weights, so top-down feedback is energy-determined, not a separate controller.
  - _caution:_ HAM writes structured/role-like attractors only via an end-to-end gradient objective (BPTT). The card flags: 'Top-down feedback can become controller-shaped if routed adaptively.' The energy-tied feedback is anti-homunculus-clean; an adaptively-routed variant would not be.

- **arxiv:2502.05164** (primary_opened=True): In-Context Denoising frames a trained attention layer as a single gradient-descent step on a context-aware DAM energy landscape, where training writes a noisy->clean association by learning projections (the attention weight matrix and value projections) that RESHAPE the energy landscape — an offline gradient dynamic — rather than modifying stored patterns or applying a runtime if-then rule. 'The association is written offline via gradient descent, not at runtime.'
  - _caution:_ I opened the abstract + a WebFetch of the PDF that returned only abstract/section-level paraphrase, not verbatim loss equations. Treat the loss form as card-level until the full text is read. This is a transformer/attention setting, not FHRR; the 'denoising target' is the clean token, which supplies the supervisory signal an unsupervised consolidation pass lacks.

- **pmc:PMC12017325, arxiv:2411.05849** (primary_opened=True): Input-Driven Plasticity (IDP) makes the synaptic matrix an instantaneous function of the input, W(u(t)) = (1/N) sum_mu alpha_mu(t) xi_mu xi_mu^T with saliency alpha_mu(t) = [xi_mu^T u(t)]^2, which RE-WEIGHTS existing memories' basin depths ('the greater the saliency weights, the deeper the associated energy minima'). It is a TRANSIENT landscape tilt that reverts when the input changes and writes NO persistent new attractor: 'no new memory is written... When u disappears, the mechanism reverts.' The paper explicitly defers a real learning rule to future work.
  - _caution:_ This is the decisive negative result for the project. IDP is anti-homunculus-clean (deeper wells auto-attract via local energy) but it CANNOT write role structure: it only re-ranks basins that already exist. The project's report 063 E1 spike was explicitly modelled on this IDP shape (Betteti et al. 2025) and failed monotonically — sharpening an unwritten signal pushed the role-target AWAY (rank 205->498).

- **reports/062** (primary_opened=True): The project's own MHN stores patterns as-is: store() appends the raw pattern vector to a list (_patterns) and retrieval is X^T softmax(beta X s) over that matrix, with no objective that modifies stored vectors. There is no gradient-on-a-target step anywhere in the storage path; the role-target vector sits in _patterns as one atom among ~1064.
  - _caution:_ Code-confirmed in src/energy_memory/memory/torch_hopfield.py store() line 74; the empirical consequence (role-target never wins) is reports/062-064.

- **reports/062, reports/063** (primary_opened=True): Across FOUR retrieval families (D1 storage/pseudo-inverse, D3 cross-K coupling, E1 landscape field, M1 weighted-MHN) hit_role = 0.000 EXACTLY for every seed x cue, and interventions that SHARPEN the representation made role-recovery monotonically WORSE: D1 pseudo-inverse rank_role 205->403 (062); E1 sharper landscape 205->246->333->498 with ΔE going monotonically negative (063). This is an anti-OVERLAP signature: if the role signal were merely buried under crosstalk, sharpening would surface it; instead sharpening degraded it, indicating the structure is FLAT/ABSENT — never written.
  - _caution:_ rank_role at baseline (~205/1064) is BELOW random-middle (~532), so a very faint elevation exists, but hit_role=0.000 means it never wins. M1 (064) gives rank_role 453-540/1024, statistically indistinguishable from random.

- **reports/064** (primary_opened=True): The M1 role-weight matrix IS non-degenerate (mean normalized row entropy 0.887; only 2.5% uniform rows; it differentiates atoms by role) yet still 'they just don't point at role-target basins during M1 settling' (064). A correct, role-discriminative READOUT exists over the substrate; the BASIN it would read does not. This cleanly separates 'readout problem' (solved) from 'writing problem' (unsolved) and is why GSBC (a cleaner readout) is correctly PARKED.
  - _caution:_ Confirms the kickoff-seed diagnosis: the failure is structural absence in the stored landscape, not crosstalk in the readout. A cleaner algebra cannot recover structure consolidation never laid down.

- **pdf:dense-associative-memory-2016, pdf:ham-2021, arxiv:2502.05164, pdf:hen-2024, reports/064** (primary_opened=True): The literature offers a clear writing mechanism that the project lacks: every DAM/MHN variant that produces discriminative/role-like basins does so via a GRADIENT ON A TARGET (DAM backprop on labels; HAM BPTT; In-Context Denoising offline gradient on clean targets), OR via a learned pre-encoder that improves separability (HEN). The project stores atoms as-is with no target and no separability objective, so the role-target occupies the same basin-depth distribution as a random atom.
  - _caution:_ The literature 'supports' that a target objective writes basins; the project has 'shown' (062-064, n=3 smoke, not n>=10+CI) that store-as-is does not. The gap is a missing supervisory/target signal — which is exactly where the anti-homunculus risk concentrates (who supplies the target without a controller?).

## Mechanisms for writing role structure

### Gradient-on-a-target consolidation (DAM/HAM-style offline error-driven pass)  [pdf:dense-associative-memory-2016, pdf:ham-2021, arxiv:2502.05164]
- AH-shape: offline-statistic — Quantity that moves locally: the stored vectors / projection weights, moved by the gradient of a FIXED loss in a batch pass. The 'decision' lives in consolidation (offline gradient), not a runtime metric-reader. Anti-homunculus-clean ONLY IF the target is supplied by a fixed dynamic (e.g. the role-cue's own bound structure, or a self-supervised denoising target derived from the data), NOT by a supervisor that picks which atom should win. STATUS live policy permits error-driven updates in batch-offline passes and BANS them online. The homunculus risk is entirely in WHERE THE TARGET COMES FROM: a label-like target = smuggled controller; a target that is a fixed function of the cue (denoise-to-clean, or unbind-then-rebind) = clean.
- maturity: proven-in-paper
- how it writes: An offline/batch consolidation pass minimizes a loss whose target makes the role-target the low-energy completion of a role-cue: starting from random/stored vectors, gradient descent moves the stored memory vectors (and/or a projection) so that the role-cue's energy-minimizing fixed point IS the role-target. This deepens the role-target basin relative to competitor atoms — the basin is written by the gradient, not by storing the atom. DAM does this with backprop on classification targets; HAM with BPTT over assembled attractors; In-Context Denoising with an offline gradient on clean targets.
- relevance: This is the single mechanism class the literature shows actually WRITES discriminative basins, and it is precisely what the project's store-as-is consolidation omits. It directly targets 'the role-target sits where a random atom sits' by moving the target to a deeper basin. The Stage-1 write-then-read go/no-go in the kickoff seed is exactly a test of this. Caution: needs a control showing the written basin generalizes (not memorization of the toy) and a target source that survives the anti-homunculus filter.

### Learned pre-encoder for separability (HEN-style)  [pdf:hen-2024]
- AH-shape: offline-statistic — The encoder is trained offline; at runtime it is a fixed map (no metric-reading). Clean as long as the encoder objective is fixed and unsupervised (reconstruction/contrastive separability), not a router that inspects retrieval outcomes. Quantity that moves: encoder weights, offline.
- maturity: proven-in-paper
- how it writes: A learned encoder maps inputs into a latent space where role-bearing patterns are more SEPARABLE before they are stored in the MHN; decode on recall. By increasing the angular separation between the role-target and competitor atoms, it raises the role-target above the metastability threshold so its basin becomes recoverable. The writing is in the encoder's training objective (reconstruction/separation), not in the MHN store step.
- relevance: Addresses the separability root cause HEN names: metastable states come from weak pattern separability, which is exactly our regime (role-target indistinguishable from random atoms). BUT it only helps if the role signal is PRESENT and merely entangled — the project's anti-overlap evidence (062/063) says the signal is absent, not entangled, so a separability encoder alone is unlikely to manufacture it. Best used in combination with a target objective, or as a separability drill-down on whatever the gradient-write produces.

### Pattern multiplicity / storage-count basin-prior  [arxiv:2603.20115]
- AH-shape: offline-statistic — Multiplicity is a storage-time count (offline statistic), not a runtime decision — clean IF the count is a fixed function of local data statistics. It becomes a thermostat ONLY if a supervisor chooses which patterns to duplicate after inspecting retrieval results.
- maturity: speculative
- how it writes: Storing a target pattern multiple times (or with higher weight) in the bank deepens/widens its basin and raises its retrieval prior, making it win over single-copy competitors. As a consolidation analog: replay frequency that is a fixed function of a local statistic (e.g. co-occurrence count or surprise) would write a deeper basin for frequently-replayed role-targets without any runtime arbitration.
- relevance: I only obtained the ABSTRACT (link-only), and the 2603.20115 abstract turned out to be a protein-design conditioning paper using a runtime attention-logit bias knob, NOT a clean basin-multiplicity storage result. So the multiplicity->basin-depth relation is asserted from general MHN theory, not from an opened primary. Useful as a cheap lever to test (does replaying the role-target more deepen its basin?), but it deepens a basin AROUND an existing atom — it still does not write a role->target ASSOCIATION (the association, not the atom, is what is missing). Treat as card-only / speculative.

### Input-driven plasticity landscape tilt (IDP / Betteti-style)  [pmc:PMC12017325, arxiv:2411.05849, doi:10.1126/sciadv.adu6991]
- AH-shape: local-dynamic — Anti-homunculus-clean as a RETRIEVAL dynamic (deeper wells auto-attract via local energy gradient; no metric-reader, no controller). But it is the wrong TOOL for the writing question: it has no consolidation/learning step and the authors explicitly defer a real learning rule to future work.
- maturity: proven-in-paper
- how it writes: Does NOT write persistent structure. The input transiently reshapes the energy landscape by re-weighting existing memories (alpha_mu = [xi_mu^T u]^2), deepening basins aligned with the current cue. It surfaces structure that is ALREADY stored; it lays down nothing that persists after the cue is removed.
- relevance: This is the cautionary case. The project's E1 spike (report 063) implemented exactly this IDP-style landscape field and failed monotonically (rank_role 205->498). The lesson: a local landscape-tilt readout CANNOT recover a basin that was never written. IDP confirms the diagnosis rather than offering a fix — it belongs in the 'fails to write' column.

### Energy-function / kernel redesign (Fenchel-Young sparse retrieval, Epanechnikov/LSR energy)  [arxiv:2411.08590, arxiv:2506.10801, arxiv:2008.02217]
- AH-shape: local-dynamic — An energy-function design choice is a fixed local dynamic, not a controller — clean. But it operates on already-written vectors; it is a sharper readout, not a writer.
- maturity: plausible
- how it writes: Changes the energy nonlinearity (sparsemax/entmax via Fenchel-Young losses enabling exact single-pattern or structured-association retrieval; Epanechnikov/LSR kernels altering the number and shape of minima). This changes how SHARPLY and how EXACTLY already-stored patterns are separated into basins, and (Fenchel-Young SparseMAP) can retrieve pattern ASSOCIATIONS rather than single patterns.
- relevance: Card-only: all three returned ABSTRACT-level detail only (link-only, not opened primaries). Same failure mode as beta-sharpening: if the role-target basin was never written, a sparser/exacter energy cannot create it — and the project's anti-overlap evidence predicts it would, like E1, make recovery WORSE. The SparseMAP 'retrieve associations not single patterns' angle is the only part that touches the writing question and would need a full read before it is load-bearing.

## Cautions
- Three of the four 'writer' literature mechanisms (DAM, HAM, In-Context Denoising) write basins via a GRADIENT ON A TARGET. The entire anti-homunculus risk for the project concentrates on WHERE THE TARGET COMES FROM. A label-like or supervisor-chosen target is a smuggled controller; only a target that is a fixed function of the cue/data (denoise-to-clean, unbind-then-rebind the role, self-supervised reconstruction) survives the filter. Any Stage-0 precommit MUST name the target source and pass the anti-homunculus check on it.
- IDP (the one mechanism whose full text I opened among the 'plasticity' candidates) does NOT write persistent structure — it is a transient retrieval-time tilt. The project already tried this shape (report 063 E1) and it failed monotonically. Do not re-propose a landscape-field/IDP readout as a writer; it belongs in the 'fails' column.
- beta / energy-nonlinearity / sparse-kernel redesigns are READOUT sharpeners, not writers. The project's anti-overlap evidence (062/063: sharpening moved rank_role 205->403/498) predicts these will make role-recovery WORSE, not better, because there is no written signal to sharpen. This is the strongest empirical caution against the GSBC/cleaner-readout family and confirms GSBC is correctly parked.
- link_only sources 2008.02217, 2506.10801, 2410.13866, 2411.08590, 2603.20115, 2412.05562 are NOT load-bearing: I obtained only abstract-level WebFetch detail, no full-text equations. Per the promotion rule, a full source card from the primary must be written before any of them carries weight in a design. In particular 2603.20115 (pattern-multiplicity) is a protein-design conditioning paper, not the clean Hopfield basin-multiplicity result its tag implies.
- The empirical anchors (062/063/064) are n=3-seed SMOKE runs (30 cues), explicitly below the n>=10 + CI graduation bar. The hit_role=0.000 and anti-overlap-sharpening results are robust across the smoke, but 'the project has SHOWN structure was never written' is a smoke-strength claim, not a graduation-strength one. A write-then-read toy (kickoff Stage 1) is the right next test, not another retrieval-family smoke.
- Phase 5-prime is PAUSED per STATUS. The ΔE role-vs-content-prior headline (phase-5-unified-design.md:282-297) and the saturating raw_scene_energy_v0 / arbitration-shaped min_branch audit findings are fenced. Any consolidation-objective work that touches Phase-5 evaluation requires the user to lift the fence first; the active branch (consolidation/role-structure) does not touch Phase 5-prime by design.

## Gaps
- No opened primary gives a worked, anti-homunculus-clean recipe for the target signal in an UNSUPERVISED consolidation setting. DAM/HAM/denoising all assume an externally-supplied target (label or clean token). The literature gap the project must close itself: what fixed dynamic supplies 'the role-target should be the low-energy completion of this role-cue' without a controller? Candidate: unbind-then-rebind the role from the cue as a self-target (FHRR-native), but no paper in this cluster demonstrates it.
- In-Context Denoising (2502.05164) is the closest 'self-supervised target writes a basin' result, but I only read abstract/section-level paraphrase, not the loss equation. The full derivation (is the writing on the stored patterns or only on a projection? does it apply to FHRR-style bound vectors?) needs a full-text read before it can ground a consolidation objective.
- No source in this cluster operates in FHRR / VSA-bound representations. All are real-valued MHN/attention. Whether a gradient-on-a-target consolidation writes a recoverable basin in the project's complex-phasor FHRR substrate (where the readout is native unbinding, not learned projection) is untested in the literature AND in the project — this is precisely the Stage-1 write-then-read go/no-go.
- The multiplicity/replay-frequency lever (write a deeper basin by replaying the target more) is asserted from general theory but has no opened primary and was partially tried as range-shaped replay (Report 111, closed as novelty-without-retrieval). Re-read 111 before proposing replay-frequency as a writer; it may already be in the graveyard.
- Whether HEN-style separability and a gradient-write COMPOSE (encoder makes the written basin more recoverable) is untested — could be a cheap drill-down once Stage-1 shows any written signal at all.

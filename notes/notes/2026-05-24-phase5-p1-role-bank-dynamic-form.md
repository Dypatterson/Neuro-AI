# Phase 5 P1 Role-Bank Construction & Atom-to-Role Assignment — Dynamic Form

Companion to the
[Phase 5 rescue brainstorm](../../brainstorm-workspace/2026-05-24-phase5-rescue/brainstorm-phase5-rescue.md)
(Tier-1 Idea P1, "Per-role coupled MHN codebooks") and the reviewer
agent audit of that brainstorm (2026-05-24, CONDITIONAL on P1
role-assignment dynamics being substrate-shaped). The brainstorm
proposes replacing the single MHN energy
`E(q) = -lse(β · X q)` with a sum over roles:

```
q_r = unbind(cue, r)               # FHRR: cue ⊛ r*
E_r(q_r) = -(1/β) lse(β · X_rᵀ q_r) + ½‖q_r‖²
E_total(q) = Σ_r w_r · E_r(q_r)    # additive over roles
```

The brainstorm's anti-homunculus check passes for the **retrieval
path** — each branch is gradient flow on its own additive term, role
is a coordinate of the energy. The reviewer agent flagged that the
check is conditional on **how the role bank R and the per-role
codebooks `{X_r}` are constructed**. This note pins down that
construction as substrate-dynamic, not as an offline algorithm with
hyperparameters set by reading a separability score.

Like the 2026-05-20 dynamic-form notes, this is **design-only**. No
implementation commitment until anti-homunculus reviewer audit + a
separate decision.

## What this session is for

Per the 2026-05-09 framing:

> Every proposed addition to the architecture must either be a local
> geometric dynamic or be expressible as a measurement of one — never
> an arbitration over them.

> An actuator is a slow-timescale dynamic that some diagnostic happens
> to be a fast-timescale snapshot of.

P1's runtime retrieval is a clean dynamic. The risk lives in two
upstream steps that have, until now, been hand-waved:

1. **Role-bank construction**: where does the role inventory `R = {r_1,
   …, r_K}` come from? If "run k-means with k chosen by elbow," P1
   imports a controller.
2. **Atom → role codebook attribution**: how does a consolidated atom
   `a_i` end up contributing to `X_r`? If "assign atom_i to X_r
   whenever count(atom_i, r) > τ," P1 imports a controller.

The session's question: **what slow-timescale dynamic is "role r is in
the bank" a fast-timescale snapshot of, and what slow-timescale
dynamic is "atom_i belongs to X_r with weight w" a fast-timescale
snapshot of, such that both are local geometric quantities rather than
an implementer's declaration?**

## The substrate primitives we already have

Before designing new mechanism, enumerate what the project's substrate
already gives us for free:

- **FHRR position vectors** (`src/energy_memory/phase2/encoding.py`).
  Window position-keys `p_0, p_1, …, p_{W-1}` are already used as
  binding roles. They are deterministically constructed from a seeded
  FHRR generator and *do not need to be discovered* — they are part of
  the architecture.
- **The emergent codebook** grows via Hebbian reinforcement; atoms
  that are heavily retrieved get reinforced. This is the substrate's
  native "what counts as a load-bearing entity" dynamic.
- **The slow-store filter** (Phase 4 post-death survivors). Atoms that
  survive death are ranked by `effective_strength`, which is itself a
  frequency-weighted Hebbian quantity. The slow-store IS the
  substrate's existing emergent inventory of "things worth keeping
  around."
- **Replay traces** capture which atoms co-activated with which
  bindings during retrieval. The replay buffer already contains the
  (atom, role-position, content) tuples we'd need to attribute
  binding counts.

The clean reading of P1 is: **the role bank is just the FHRR
position-vector inventory, and per-role codebooks are weighted
slow-store atoms by their binding-frequency to each position vector,
where binding frequency is measured from replay traces.** Nothing
new is built; existing substrate properties are *measured* and used
as the energy-function's role coordinates.

## Role-bank construction (the slow-timescale dynamic for R)

**Specification.** The role bank `R` for Phase 5 is the FHRR
position-vector inventory:

```
R = {p_0, p_1, …, p_{W-1}}
```

where `p_w` is the deterministic FHRR position vector for window
position `w`, generated by the existing
`PositionVectors(seed=…, dim=D).vectors[w]`
([phase2/encoding.py](../../src/energy_memory/phase2/encoding.py)).
`W` is the window size used in Phase 2 encoding. **The role bank is
the same inventory used to encode windows; no new bank is constructed.**

**Anti-homunculus reading.** "Role r is in the bank" is *not* the
output of a clustering algorithm reading a separability metric. It is
a categorical fact about the substrate: position vectors are
architectural primitives, generated once at seed time and never
re-chosen. The slow-timescale dynamic this is a snapshot of is the
choice of `W` itself, which is a substrate hyperparameter (the same
shape as `D`, `β`, or the FHRR generator seed). No metric is read; no
selector fires.

**What this rules out.**
- Discovering roles by clustering slow-store atoms (would be
  metric-driven k chosen offline).
- Adding/removing roles based on usage (would be a controller
  reallocating capacity by reading metrics — see also the M3 failure
  mode flagged in the brainstorm).
- Treating "role" as anything other than an FHRR position vector for
  Phase 5. A future phase may extend the role bank to syntactic /
  relational roles (e.g. agent/patient, subject-of), but those
  extensions need their own dynamic-form note and audit.

**What this commits to.** Phase 5's "role" is identical to Phase 2's
"position." The role-prior vs content-prior distinction collapses
onto a position-prior vs content-prior distinction — branches are
seeded by *which window position the cue's binding suggests* vs
*which content the cue resembles*. This is a *narrowing* of P1 vs
the brainstorm's framing; the narrowing is what makes it audit-clean.

**Future generalization path.** If/when the project introduces
non-positional roles (a Phase 6 or beyond decision), they enter `R`
by becoming heavily-used binding keys in the emergent codebook —
i.e. an atom that is repeatedly used as the *first operand* of a
binding `bind(a_i, ·)` is promoted to `R` once its first-operand
binding frequency crosses the same survival threshold the codebook
already uses for atoms (Hebbian saturation, then survival under
death). No new mechanism, no threshold-reading selector — the same
death/survival dynamic the codebook already runs. Out of scope for
this note; flagged for future design.

## Atom → role attribution (the slow-timescale dynamic for w_{i,r})

**Specification.** For each slow-store atom `a_i ∈ X` (the post-death
survivors that Phase 5 currently uses as schemas), maintain a per-atom
per-role binding-count vector `c_{i,r}` that accumulates during
replay/consolidation:

```
c_{i,r}(t+1) = c_{i,r}(t) + 𝟙[atom a_i was bundled with role r in
                              the consolidated atom at step t]
```

The check `𝟙[atom a_i was bundled with role r]` is a substrate
operation, not a similarity metric: it reads off whether `a_i` was a
factor of `bind(r, ·)` in the encoded window that produced this
consolidated atom. The Phase 2 encoder already produces this binding
graph; we just need to record it (lightweight provenance addition to
replay traces).

**Provenance source — load-bearing commitment (closes the chicken-
and-egg risk).** `c_{i,r}` is incremented **strictly from encoder-time
(atom, role) provenance carried in the replay trace** — never from
runtime unbinding of consolidated atoms. The encoder at
[`phase2/encoding.py:32`](../../src/energy_memory/phase2/encoding.py)
explicitly constructs each bundled term as
`bind(positions[index], codebook[token_id])` — the (atom, role) pair
is a structural fact at encode time, available as a dictionary lookup
on the encoded window's term list.

This commitment matters because the alternative — recovering (atom,
role) provenance post-hoc by unbinding consolidated atoms by every
role in `R` — would make `c_{i,r}` depend on the unbinding fidelity
of the very substrate P1 is supposed to fix. That would be the same
chicken-and-egg failure mode as P4's `f*`-from-Hebbian-retrieval
collapse (audit 2026-05-24): a count that quietly bakes in a noise-
floor threshold below which atom-role pairs are "not detected" is a
metric-driven categorization, even if no `if` statement is visible.

**Replay-trace schema check (commit gate before P1 implementation
lands).** Confirm the existing replay trace stores the per-window
encoder term list — i.e. the sequence of (position-index, token-id)
pairs that fed each bundled atom — and not just the bundled output
vector. If yes, `c_{i,r}` accumulation is a dictionary lookup on the
trace and the ~50 LOC budget in `phase4/consolidation.py` is
plumbing of pre-existing facts. If no, the trace schema must be
extended to carry encoder-time provenance **before** P1 lands;
P1 must not work around the missing provenance by post-hoc
unbinding.

**Initial-condition rebuild.** "Rebuild `c_{i,r}` from the existing
replay trace history" in the Initial Conditions section below refers
to this same encoder-provenance source — a one-shot offline scan of
recorded trace tuples, never a substrate re-run.

The atom's contribution weight to per-role codebook `X_r` is the
normalized frequency:

```
w_{i,r} = c_{i,r} / max(ε, Σ_{r' ∈ R} c_{i,r'})
```

where `ε` is a small float-precision floor (numerical stability, not
a metric threshold). Each atom contributes to every per-role energy
`E_r` with weight `w_{i,r}`. An atom that bound 70/30 between two
roles contributes to both their codebooks, weighted accordingly. An
atom that has never bound with role `r` has `w_{i,r} = 0` and does
not contribute to `E_r`.

The per-role energy becomes a **weighted** Hopfield energy:

```
E_r(q_r) = -(1/β) lse(β · diag(w_{·,r}) · X q_r) + ½‖q_r‖²
```

equivalent to evaluating the standard MHN log-sum-exp on a codebook
where each row `x_i` is pre-scaled by `w_{i,r}`. **No atom is
"assigned" to a single codebook; the attribution is the soft weight
on every codebook.**

**Lyapunov-and-basin-faithfulness of `diag(w)·X` MHN — substrate-
validity gate (NOT anti-homunculus, but blocking).** Standard
Ramsauer log-sum-exp `E(q) = -(1/β) lse(β · X q) + ½‖q‖²` is a known
Lyapunov function whose basins sit at the unit-magnitude rows `x_i`
of `X`. Pre-scaling rows by `w_{i,r} ∈ [0,1]` is mathematically still
a scalar function of `q_r`, so gradient flow is still on a single
energy — that's why the anti-homunculus shape passes. But the
*basins* shift off the unit-magnitude pattern vectors toward the
origin in proportion to row weight, and downstream FHRR consumers
(unbind, decode) expect approximately unit-magnitude state.

Plausibility: the Hsu/Frady 2024 attention-based resonator
([arXiv:2403.13218](https://arxiv.org/abs/2403.13218), eq. 8) uses
exactly this weighted form for per-factor codebooks — soft attention
weights pre-multiplying `X_j` rows — and the paper reports stable
factorization on FHRR. That is the published precedent. But the
analysis there assumes weights derived from the resonator dynamics
itself, not from external frequency attribution; the basin geometry
under our `c_{i,r}`-derived weights is not literally proved.

**Commit gate before P1 implementation lands.** Numerical Lyapunov
+ basin-magnitude check on a small synthetic substrate (single
seed, small `D`, ~5 roles, ~50 atoms): verify that (i) per-role
energy descends monotonically across settling iterations and (ii)
converged `q_r` magnitude stays within e.g. 30% of unit. Both
substrate-pure measurements, no readouts. Half-day spike, sequenced
before the full Phase-5 control matrix.

**Failure-mode contingency.** If the `diag(w)` pre-scale breaks
basin faithfulness, the obvious alternative is to pull the weights
*outside* the LSE — e.g.
`E_r(q_r) = -(1/β) Σ_i w_{i,r} · lse_i(β · ⟨x_i, q_r⟩)` or, more
straightforwardly, a per-pattern logit prior `-(1/β) lse(β · X q_r
+ log w_{·,r})`. **The logit-prior form is exactly Path-C-shaped at
the per-role level and would re-introduce Path C's failure mode
(energy margin without structural retrieval, hit_role≈0).** P1
should refuse the logit-prior fallback and instead either accept the
substrate-fragility result (P1 doesn't work cleanly on this
substrate) or seek a different weighting scheme that preserves
in-LSE multiplication (candidate: row-normalize `diag(w)·X` so each
weighted row remains unit-magnitude — algebraically clean,
substrate-validity to be checked in the same spike).

**Top-level outer weight `w_r`**. The total energy
`E_total = Σ_r w_r · E_r` needs role-bank weights `w_r`. Per the same
substrate-dynamic principle:

```
w_r = (Σ_i c_{i,r}) / (Σ_{r' ∈ R} Σ_i c_{i,r'})
```

— the global frequency with which role `r` has been bound in
consolidated atoms. Roles that are heavily used contribute more to
total energy. **Not a controller**: `w_r` is a normalized
co-occurrence count, the same shape as `w_{i,r}`.

**Substrate-design choice flag.** Uniform outer weighting
`w_r = 1/|R|` is *also* anti-homunculus-clean (a fixed substrate
parameter, same shape as `D` or `β`). The choice between
frequency-weighted `w_r = (Σ_i c_{i,r}) / (Σ_{r'} Σ_i c_{i,r'})` and
uniform `w_r = 1/|R|` is a substrate-design call to be evaluated
empirically, not a default to ride. For Phase 5's narrowing where
`R = {p_0,…,p_{W-1}}` and binding frequency across window positions
is approximately uniform by construction (every encoded window uses
every position once), the two formulations are numerically close
and the empirical decision matters little. For future non-positional
role banks where binding frequency varies sharply across roles,
frequency-weighted `w_r` systematically suppresses rare-role
retrieval — which may be substrate-legitimate ("rarely-used roles
are weakly supported") or substrate-fragile ("a Phase 6 rare-role
discovery would be invisible"). The Phase 5 implementation should
default to frequency-weighted `w_r` (to match the per-atom shape of
`w_{i,r}`) but report numerical comparison to uniform `w_r` as a
drill-down.

**Anti-homunculus reading.** "Atom_i contributes weight w to
codebook X_r" is *not* the output of a threshold rule. It is a
substrate co-occurrence statistic, structurally identical to how
Hebbian weight updates everywhere else in the project work — the
slow-timescale dynamic this is a snapshot of is the long-run binding
distribution of each atom across roles, which is itself produced by
the encoder + consolidation dynamics. The 2026-05-09 note's standard
non-controller pattern (section 6.4, "consolidation gate threshold
rises with d̄ so spread atoms naturally get smaller updates without
anyone reading d̄") is the exact template: nobody reads `c_{i,r}` to
decide anything; the soft weight IS the dynamic, applied uniformly
to every atom × role pair.

**What this rules out.**
- Hard thresholded ownership (`if c_{i,r} > τ assign atom_i to X_r`).
- Tie-break rules (`if c_{i,r} ≈ c_{i,s}, route to whichever codebook
  has fewer atoms`).
- Per-cue dynamic re-weighting (`scale w_{i,r} based on cue
  similarity` — would be a controller reading a runtime metric).
- Cleanup operations that prune atoms with low `w_{i,r}` from
  `X_r` (would be a metric-driven selector).

**What this commits to.** Every consolidated atom contributes to
every per-role energy with a normalized frequency weight; the soft
weight is the only assignment mechanism. Atoms with `w_{i,r} = 0` for
some r contribute nothing to that role's energy by construction (the
multiplication zeroes them out), so the per-role codebooks are
naturally sparse without anyone running a sparsification pass.

## Initial conditions

Bootstrapping `c_{i,r}` at Phase 5 start: rebuild from the existing
replay trace history (or from a fresh consolidation pass over the
slow-store substrate, recording per-atom per-role binding counts).
This is a one-shot offline computation, not a runtime decision. No
metric threshold is read.

For atoms that have no binding history (newly-added atoms during a
Phase 5 run, if any), use a **uniform prior** `c_{i,r} = 1` for all
r ∈ R. This makes the new atom contribute equally to every per-role
codebook until its actual binding history accumulates — analogous to
the discovery-channel `r_ema = 0` initial condition from the
2026-05-20 note, but with the symmetric default of "uniform" rather
than the categorical "novel" claim.

**Anti-homunculus reading of the uniform prior.** "Uniform until data
arrives" is a fixed-prior substrate property, not a controller.
Equivalent to a Laplace smoothing constant.

## Falsification criteria

For P1 with this role-bank spec to graduate Phase 5, the following
must hold (alongside the existing Phase 5 graduation criteria from
[phase-5-unified-design.md:269-292](../emergent-codebook/phase-5-unified-design.md)):

1. **Headline ΔE structural pass.** `ΔE = E_content − E_role` is CI
   strictly above zero AND ≥ 5.5e-3 floor, n_seeds ≥ 10.
2. **`hit_role` materially above random** (≥ 0.05; current Path C
   value is 0.003). This is the structural-retrieval test that Path
   C failed — the per-role energies should drive role-target basin
   retrieval, not just energy-margin manufacturing.
3. **`rank_role` materially below random.** Current value 443/489 ≈
   uniform. If P1 works, role-target atoms should rank in the top
   decile (rank < 50).
4. **`random_lowest` near 1/3 chance, not the 0.37–0.46 inflated
   value.** Random-prior branches must not systematically land
   lowest, which would re-indicate arbitration-shape (the no-schema-
   store positive-control failure mode from Report 061).
5. **Per-role codebook utilization.** Drill-down: at least 30% of
   slow-store atoms have nontrivial `w_{i,r}` for at least two roles
   (avoids degenerate "every atom is mono-role" outcome which would
   collapse the per-role energies back to the single-codebook case).
6. **Phase 4 W=3 meta-stable rate non-regression** (G1 gate from
   [phase-5-checklist.md](../emergent-codebook/phase-5-checklist.md)).

If criteria 1+2+3 pass and 4+5 fail, the per-role energies are
mathematically working but the attribution is degenerate — report as
substrate-fragile, do not graduate.

If criterion 1 passes but 2 or 3 fail, the same Path-C-style energy-
margin-without-structural-retrieval failure has recurred — P1's
spec was implemented wrong (likely hard thresholding somewhere) and
needs audit, not graduation.

## Anti-homunculus self-check (writing it out in full per CLAUDE.md)

| Substep | Decision lives in | Verdict |
|---|---|---|
| Role bank `R` construction | Architectural primitive (FHRR position vectors at encoder seed time) | ✅ |
| Per-atom per-role binding count `c_{i,r}` | Substrate co-occurrence statistic, accumulated unconditionally during consolidation | ✅ |
| Atom → role weight `w_{i,r}` | Normalized frequency (division by sum); same shape as any Hebbian normalization in the substrate | ✅ |
| Outer role weight `w_r` | Normalized global binding count, same shape | ✅ |
| Per-role energy `E_r(q_r)` | Standard MHN log-sum-exp on a weighted codebook (weights enter as a `diag(·)` pre-scale, which is element-wise) | ✅ |
| Total energy `E_total(q) = Σ_r w_r E_r(q_r)` | Additive Lyapunov function; gradient flow descends total energy | ✅ |
| K-branch settling under `E_total` | Gradient flow on the additive energy; each branch's seed role determines the dominant additive term but does not switch terms on/off | ✅ |
| Newly-added-atom initial `c_{i,r}` | Uniform Laplace-style prior; fixed substrate property | ✅ |

**Where would a homunculus sneak in if the implementation drifts?**

1. **Discovering roles by clustering.** A future "we need more
   expressive roles" pressure could tempt running k-means on slow-store
   atoms with k chosen by elbow. Resist; growth-via-binding-frequency
   (see "Future generalization path" above) is the substrate-dynamic
   form.
2. **Threshold-based atom pruning in `X_r`.** `if w_{i,r} < τ remove
   atom_i from X_r` is a metric-driven selector. Atoms with low weight
   already contribute negligibly (the multiplication zeroes them); no
   pruning needed.
3. **Per-cue rescaling of `w_{i,r}`.** `scale w_{i,r} by
   cosine(cue, atom_i)` would convert the soft attribution into a
   runtime selector. The attribution must remain a long-run
   substrate statistic, not a per-cue computation.
4. **Capacity reallocation.** `if X_r has fewer than N atoms, boost
   weights to fill it` reads a metric and triggers a response. The
   substrate's natural sparsity is the only capacity dynamic.
5. **Routing module in front of `E_total`.** Computing branch-specific
   `E_total` based on the branch's seed prior is a router. The whole
   `Σ_r w_r E_r` must be evaluated uniformly; differences across
   branches come from the different `q_r = unbind(cue, r)` values, not
   from selecting which `r` terms to include.

If any of (1)–(5) appears in the implementation PR, the reviewer
agent should reject and this note should be revisited.

## Implementation budget

This is a design-only note. Implementation budget is decided
separately. Sketch of what would be needed, with **two pre-
implementation spikes** added per the 2026-05-24 reviewer-agent audit:

**Pre-implementation spikes (sequenced first).**
- **Spike S1 — Replay-trace schema check.** Confirm the existing
  replay trace stores per-window encoder term lists, not just bundled
  output vectors. Read-only inspection of
  `phase4/consolidation.py` and the replay buffer schema. If the
  trace already carries encoder-time (atom, role) provenance, S1
  closes Risk B. If not, scope the schema extension (estimated +30
  LOC) and re-audit before P1 lands. **Half-day.**
- **Spike S2 — Numerical Lyapunov + basin-magnitude check.**
  Synthetic substrate (single seed, `D=512`, ~5 roles, ~50 atoms);
  run `diag(w)·X` MHN settling for ~12 iters; verify (i) per-role
  energy descends monotonically and (ii) converged `q_r` magnitude
  stays within e.g. 30% of unit. Closes Risk A. If both pass: P1
  unblocks. If (i) fails: P1 is wrong shape; revisit. If (ii) fails:
  try row-normalized `diag(w)·X` fallback (in-LSE, anti-homunculus
  preserved); explicitly forbid the logit-prior fallback (Path-C-
  shape recurrence). **Half-day.**

**Main implementation (after S1 and S2 both pass).**
- **Replay-trace provenance plumbing.** ~50 LOC in
  `phase4/consolidation.py` to record per-atom per-role binding
  counts from encoder-time tuples (adjusted upward if S1 requires
  schema extension).
- **Per-role weighted MHN energy.** ~30 LOC extension to
  `memory/torch_hopfield.py` taking a per-role weight vector
  (`diag` pre-scale, row-normalized if S2 required the fallback).
- **Outer additive energy.** ~20 LOC in a new
  `phase5/role_factored_energy.py` summing `Σ_r w_r E_r` (with
  `w_r` configurable between frequency-weighted and uniform per the
  substrate-design choice flag, defaulting to frequency-weighted).
- **K-branch loop using `E_total`.** Existing K-branch code paths
  swap `E` for `E_total`; ~20 LOC of plumbing.

Total: ~120 LOC + ~1 day of spike work, plus tests. Tractable for a
one-week implementation engagement after S1 and S2 close.
